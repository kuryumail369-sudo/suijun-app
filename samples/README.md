# OCR検証用の検体（電子レベルの液晶）

液晶OCRの読み取り精度を確かめるための実機写真。**モデル・送信解像度・プロンプトを
変更したときは、必ずここの写真すべてで読み直し、下の期待値と一致するか確認する。**

## 期待値（全ファイル共通）

同じ表示を条件を変えて撮影したもの。どの写真も正解は同じ。

| 項目 | 正解 |
|---|---|
| 標尺読み値 Rh | **1.055** m |
| 水平距離 Hd | **12.53** m |

## 使い方の原則

**トリミングしないこと。** 液晶が画面いっぱいに写った理想的な写真では、現場で実際に
起きる誤読を再現できない。検体は現場の構図のまま保つ。

**全部が読めることを目標にしない。** 12（ぶれ強め）のように、人間でも読み取りに
自信が持てない写真は「読めない」と返すのが正しい挙動。無理に読んで誤った値を
入れるより、null を返して手入力を促すほうが安全。

## 既知の誤読

- **2026-09-17**: Hd 12.53 を **14.63** と誤読（Rh 1.055 は正解）。
  7セグの 2/4、5/6 が近い形になるため。液晶の下段は上段より文字が小さく、
  距離のほうが誤読しやすい。
  → 対策：確認画面で、距離欄に入る場合は距離も読み値と同じ大きさで表示するようにした
    （読み飛ばしを防ぐため）。誤読そのものは無くせないという前提に立っている。

## この検体で確かめるべきこと

1. **Rh を正しく読めるか**（最重要。成果表の数値になる）
2. **Hd を Rh として入れていないか**（上下を取り違えると成果が狂う）
3. **読めない写真で、無理に数値を返していないか**（null を返すのが正解）


## 2026-09-19 モデル比較の結果

`ocrtest.html` で、12枚すべてを haiku と sonnet に読ませた。

| | haiku（採用） | sonnet |
|---|---|---|
| 正解 | 7 / 12 | 7 / 12 |
| **誤読** | **2** | **5** |
| 「読めない」と返した | 3 | 0 |

正解数は同じだが、sonnet は判別できない写真にも必ず数字を返し、07で `1.5375`、
06で `1.1027` と、正解 `1.055` からかけ離れた値を自信ありげに出した。10では
`1.065` と1桁だけ違う値を返しており、これは目視の検算でも見逃しやすい。

誤った読み値が入ると閉合差の点検をすり抜けて成果に紛れ込むため、
「読めない」と返してくれるほうが現場では安全。料金も安いので haiku を継続する。

opus は当時モデルIDが無効（または未契約）で比較できなかった。
